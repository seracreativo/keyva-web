Your keys, where you can find them.

Keyva keeps the API keys, tokens and connection strings you work with every day — encrypted on your devices, synced through your own iCloud, and never on anybody's server. Including ours.

What it does

Projects, environments, variables

The shape you already work in: one project, its development, staging and production, and the values that differ between them.

Secrets, actually secret

Marked values go to the Keychain and an encrypted store, never into the database in the clear. They sync end-to-end through iCloud.

Import and export what you have

Reads and writes .env, JSON, YAML and xcconfig. Bring a folder of dotfiles in; take a single environment out.

Nothing leaves your devices

There is no Keyva account and no Keyva server. Sync is your iCloud, between your Macs, iPhones and iPads.

Your terminal and your coding agent

Keyva ships with keyva and an MCP server, so the tools you already use can read what you store without you pasting anything. 

keyva run dev            # start the dev server with the real values injected
keyva pull production    # write a .env, 0600, and add it to .gitignore
keyva scan               # find a secret you are one commit from publishing

Point Claude Code or any MCP client at the server and it stops asking you for keys — it looks them up, and writes back the ones it generates.

Why the version from this page can do more

Everything inside a Mac App Store app runs in a sandbox, and a sandbox does not answer "not allowed" — it answers "nothing there". So the bundled server reports a clean scan of a repository full of files. This build is not sandboxed, so scanning your project, writing a .env next to your code and running commands with your values all work from inside the app, with nothing extra to install.
